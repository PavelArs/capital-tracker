# Frozen persistence and implementation interface

All new column identifiers use the camelCase spellings below. Migration 13 is
AddManualOpeningPositions1790030000000. Four typed mappings reside under
backend/src/entities/{manual-account,accounting-instrument,account-opening-snapshot,account-opening-position}.entity.ts.
Runtime schema synchronization remains disabled. No historical migration is edited.

- manual_accounts (ManualAccount): id uuid primary key generated by application;
  ownerId uuid NOT NULL references users(id) RESTRICT; requestId uuid NOT NULL;
  canonicalPayload text NOT NULL; name varchar(120) NOT NULL;
  currentRevision integer nullable; createdAt timestamptz(3) NOT NULL default clock_timestamp().
  UNIQUE(ownerId,id), UNIQUE(ownerId,requestId). Positive currentRevision when present.
- accounting_instruments (AccountingInstrument): id/ownerId/requestId/canonicalPayload/
  name/createdAt as accounts; symbol varchar(32) nullable; namespace text NOT NULL
  default manual with CHECK(namespace = 'manual'). UNIQUE(ownerId,id),
  UNIQUE(ownerId,requestId). Names and optional symbols are trimmed/nonempty/no controls.
- account_opening_snapshots (AccountOpeningSnapshot): ownerId uuid NOT NULL references
  users(id) RESTRICT; accountId uuid NOT NULL; revision integer NOT NULL positive;
  requestId uuid NOT NULL; canonicalPayload text NOT NULL; asOf timestamptz(3) NOT NULL;
  createdAt timestamptz(3) NOT NULL default clock_timestamp().
  PRIMARY KEY(ownerId,accountId,revision), UNIQUE(ownerId,accountId,requestId),
  composite FK(ownerId,accountId) to manual_accounts(ownerId,id) RESTRICT.
  asOf finite and within [1970-01-01T00:00:00.000Z,10000-01-01T00:00:00.000Z).
- account_opening_positions (AccountOpeningPosition): ownerId uuid NOT NULL references
  users(id) RESTRICT; accountId uuid NOT NULL; revision integer NOT NULL;
  instrumentId uuid NOT NULL; quantity numeric(78,30) NOT NULL;
  costStatus text NOT NULL; totalCostUsd numeric(78,30) nullable.
  PRIMARY KEY(ownerId,accountId,revision,instrumentId); composite FKs to snapshots
  and instruments scoped by owner, all RESTRICT. quantity finite and positive;
  known cost explicitly nonnull/finite/nonnegative OR unknown with literal SQL NULL.
  Numeric NaN and both infinities explicitly excluded. Revision positive.

Add account FK(ownerId,id,currentRevision) to snapshots(ownerId,accountId,revision),
RESTRICT, after both tables exist. No deferred FK is necessary: create account with
NULL, insert complete snapshot/positions, then move pointer in one transaction.
Existing UUID key ordering and snapshot primary indexes support bounded reads.
createdAt finite on all timestamped tables. No cascade-delete or down migration
that discards saved history; down refuses pending an explicit recovery plan.

canonicalPayload is deterministic JSON text of normalized input excluding requestId;
opening includes expectedRevision and positions sorted by lowercase instrumentId.
No floating-point amount conversion. Typed numeric entity properties are strings.

AccountingService constructor(DataSource), methods:
- createAccount(ownerId,input), createInstrument(ownerId,input),
  saveOpening(ownerId,accountId,input): {created:boolean,value:declaredProjection}.
- listAccounts(ownerId,{cursor?,limit?}), listInstruments(ownerId,{cursor?,limit?}).
- getAccount(ownerId,accountId).
- listOpenings(ownerId,accountId,{beforeRevision?,limit?}).

Service validates normalized/raw boundaries defensively; HTTP validation must retain
original types despite the existing global implicit conversion option. Create writes
use database uniqueness with a valid post-conflict read, never querying an aborted
transaction. Opening obtains an owner-scoped row lock before replay and CAS.

Initial maintained UI acceptance selectors: heading Ручные счета, label Название счета,
button Создать счет; detail heading equals the entered account name. Pages use
proper semantic labels/roles and Russian errors. These are useful UI labels, not
hidden selectors substituted for genuine behavior.
