## Why

An initialized account still places a long initialization explanation, revision pins and accounting limits before every operation editor. At mobile widths this pushes the primary action down the page despite the new focused workflows.

## What Changes

- Keep a short, honest accounting-scope notice visible for initialized journals.
- Move the existing coverage, revision, capacity and allocation explanation into a collapsed native disclosure labelled «Параметры и правила учёта».
- Preserve the initialization warning before uninitialized-journal actions, plus always-visible errors, conflicts and original-request recovery.
- Retain mounted editors, exact draft/File state and explicit request semantics when the disclosure is toggled or sections/workflows change.

## Capabilities

### New Capabilities
- `journal-context`: Compact, accessible journal context with exact on-demand details and retained initialization/recovery guidance.

### Modified Capabilities
None. Existing account/workflow lifecycle and financial contracts remain unchanged.

## Impact

TradeJournal presentation and scoped CSS; extend existing browser acceptance instead of adding a broad E2E suite. Depends on archived account-workspace and operation-workflow changes at93b2ae8. No API, controller, backend, schema, dependency, provider, deployment or user-data changes.

Non-goals: complete form/results redesign, editor focus navigation, portfolio/chart expansion, preview refresh and production rollout.
