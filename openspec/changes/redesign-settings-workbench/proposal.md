## Why

Settings still uses color-only section selection and cramped legacy card styling. Stored FX conversion and external collection have equal visual weight, while useful exact results follow technical timestamps. This slice advances the required whole-frontend redesign with clear everyday settings and an honest stored-data workflow.

## What Changes

- Name the three-section selector and expose selection with native pressed buttons; retain conditional mounting and keyboard focus on the selected control.
- Associate language/theme controls with visible labels and use responsive flat layout with44px targets.
- Give the FX amount associated exact-value guidance, separate stored reads from explicit provider collection, and lead the result with its exact table before timestamp evidence.
- Preserve all controllers, last-good/error/freshness/attribution output and exact financial/provider boundaries. Remove only unused invitation-code CSS after consumer search.

## Capabilities

### New Capabilities

- `settings-workbench`: accessible responsive settings navigation and focused stored FX presentation.

### Modified Capabilities

None. Existing daily-display-fx financial, collection and privacy requirements remain unchanged.

## Impact

Settings TSX/CSS, optional control IDs in language/theme switches, DisplayFxPanel TSX/CSS and the existing DFX-UI acceptance case. No API/backend/auth/schema/dependency/pipeline changes, owner data mutation or production/preview rollout. Depends on the verified application shell and daily FX capability. Broader integration-health and legacy currency-manager redesign are separate; this slice preserves its destination and clearly describes its scope.
